# معماری سیستم — مربی هوشمند پایه هشتم

## اجزا (تک‌برنامه‌ای، بدون میکروسرویس)

| جزء | فناوری | مسیر |
|---|---|---|
| سرور API | Python + FastAPI + SQLAlchemy | `server/` |
| پایگاه داده | SQLite در توسعه، PostgreSQL در تولید (فقط با `DATABASE_URL`) | — |
| پنل وب والد + وب‌اپ دانش‌آموز | React + TypeScript + Vite (PWA، راست‌چین) | `web/` |

## مدل داده

کاربر (والد/دانش‌آموز/مدیر) ← پیوند والد–دانش‌آموز؛ محتوا:
پایه ← کتاب ← فصل ← موضوع ← هدف یادگیری ← آموزش ← تمرین ← آزمون ← مرور.
هر درس و سؤال: منبع، نسخه محتوا، دشواری، پاسخ صحیح، توضیح و وضعیت بازبینی (`draft/approved`).

آزمون: `Attempt(mode=guided|independent)` — در حالت مستقل پاسخ تا پایان فاش نمی‌شود و این
تفاوت در گزارش والد حفظ می‌شود. اشتباهات فقط بر اساس شواهد دسته‌بندی می‌شوند
(مفهومی/محاسباتی/نامشخص). مرور فاصله‌دار با فاصله‌های ۱ تا ۳۰ روز بر اساس درستی پاسخ.

## آفلاین و همگام‌سازی

- وب: Service Worker + بسته دانلودی (`/api/content/download-bundle`) در localStorage؛
  تصحیح عینی روی دستگاه؛ صف پاسخ با شناسه یکتای `client_id`؛ همگام‌سازی با
  `POST /api/sync/answers` و نادیده‌گرفتن تکراری‌ها (آزمون خودکار دارد).
- اندروید: SQLite محلی با همان قرارداد `client_id`.
- مربی و تحلیل گفتار آفلاین در دسترس نیستند و این محدودیت در رابط کاربری صریح نمایش داده می‌شود.

## امنیت

گذرواژه با bcrypt، نشست JWT، کنترل نقش و مالکیت داده در سرور (دانش‌آموز فقط داده خود،
والد فقط دانش‌آموز پیوندخورده)، هیچ کلیدی در وب/اپ نیست، ضبط صدا فقط با رضایت والد.
